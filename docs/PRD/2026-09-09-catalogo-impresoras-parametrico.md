## 1. Goal

Hoy registrar una impresora exige escribir a mano marca, modelo **y** consumo en watts (3 campos manuales: `BrandSelectorField` de marcas conocidas + `TextFormField` de modelo + `NumericInputField` de watts). Esto ocurre en **2 lugares**: el paso 2 del `initial_config_page.dart` (primera vista inicial) y el form de impresora `printer_form_page.dart` (Ajustes → Catálogos → Impresoras → Nueva/Editar).

Este feature reemplaza la captura manual por un **selector paramétrico de 3 niveles**:

1. **Marca**: dropdown con el catálogo completo de marcas (29) + marcas ya registradas por el usuario + opción **"Otro..."** para marca manual.
2. **Modelo**: dropdown paramétrico con los modelos de la marca seleccionada + opción **"Otro..."** para modelo manual.
3. **Consumo (W)**: al elegir un modelo del catálogo, se **auto-completa** con el consumo promedio real de ese modelo (campo **editable** — el usuario puede corregirlo).

Todo embebido en la app (100% offline, cumple Non-Negotiable "No backend").

## 2. User Story

**Como** maker/operador de impresión 3D que registra su impresora (primera configuración o Ajustes → Catálogos)

**Quiero** elegir mi impresora desde un catálogo real: primero la marca (ej. Bambu Lab), después mi modelo exacto (ej. A1 Combo), y que el consumo eléctrico se cargue solo — con opción de corregirlo — en lugar de escribir los tres campos a mano

**Para** no tener que investigar o recordar el consumo en watts de cada máquina y reducir errores de tipeo, manteniendo el control final sobre el valor usado en el cálculo de costo eléctrico.

## 5. Assumptions

- **A1 [CONFIRMED]**: El valor auto-cargado es **consumo promedio real durante impresión activa** (no máximo de PSU). Ej: Bambu A1 Combo ≈ **100 W** promedio (medido por Bambu; 350 W es el máximo de la fuente). Ender-3 ≈ 125 W. Prusa MK4 ≈ 130 W.
- **A2 [CONFIRMED]**: El selector paramétrico se aplica en **ambos** lugares: config inicial paso 2 + form de impresora (Ajustes).
- **A3 [CONFIRMED]**: Catálogo **embebido estático** en Dart (const), 29 marcas / 174 modelos. Sin backend.
- **A4**: El campo watts es **siempre editable** — el auto-fill es un valor inicial conveniente, nunca un bloqueo.
- **A5**: En edición de una impresora existente: si `brand` está en el catálogo → dropdown de marca con ese valor; si no → modo manual ("Otro..."). Si `name` coincide con un modelo de la marca → dropdown de modelo seleccionado; si no → modelo manual. Watts se pre-carga con el valor guardado (no se pisa).
- **A6**: Los modelos con watts estimados (`(est)` en research, ~130 filas) se cargan igual; el flag `isEstimated` permite mostrarlo en UI como hint sutil ("estimado") y futuro tooling.
- **A7**: Marca "Otro..." desactiva la cascada de modelos (campo modelo manual). Modelo "Otro..." → campo modelo manual y watts manual (vacío, requerido).
- **A8**: La lista de modelos del catálogo de una marca incluye SOLO los modelos de esa marca (no cross-brand).

### 6.3 Widget `PrinterCatalogSelector`

Nuevo widget composito en `lib/features/catalog/printers/presentation/widgets/printer_catalog_selector.dart` (o `shared/widgets/` si se prefiere — decisión de implementación).

Reemplaza el par `BrandSelectorField + TextFormField(modelo)` en ambos forms. Recibe **3 controllers** (marca, modelo, watts) para que el form padre conserve la validación y el guardado intactos:

```dart
class PrinterCatalogSelector extends ConsumerStatefulWidget {
  const PrinterCatalogSelector({
    required this.brandController,   // marca
    required this.modelController,   // modelo/name
    required this.wattsController,   // se auto-llena al elegir modelo
    this.enabled = true,
    this.compact = false,            // denso para el stepper del initial config
  });
}
```

Comportamiento:
- **Marca**: dropdown = `catalogBrands()` ∪ marcas registradas por el usuario (del `printersNotifierProvider`) ∪ sentinel **"Otro..."**. Al elegir marca → resetea modelo+watts y habilita dropdown de modelo.
- **Modelo**: dropdown = `catalogModels(brand)` ∪ **"Otro..."**. Al elegir modelo del catálogo → `modelController.text = modelo` y `wattsController.text = watts.toString()` (auto-fill, editable). Al elegir "Otro..." → campo modelo manual (TextFormField), watts queda vacío (requerido).
- **Marca "Otro..."** → campo marca manual + campo modelo manual + watts manual (sin cascada).
- **Edición**: si `brandController.text` está en catálogo → dropdown seleccionado; si no → modo manual. Idem modelo. **No pisa** watts pre-cargados del registro (A5).
- Hint bajo el campo watts cuando fue auto-llenado: "Consumo promedio de {marca} {modelo} — podés editarlo" + `(estimado)` si `isEstimated`.
