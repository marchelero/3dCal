## Decisiones de diseno

1. **Features como `List<String>` getter, no 5 keys separadas**.
   Spec ofrecia dos opciones; elegi una sola key `paywallFeatures` que
   retorna `List<String>` porque:
   - Matchea el patron de "datos parametricos" (vs UI copy atomico).
   - 1 key = 1 l10n entry a mantener. Si en futuro se agrega una 6ta
     feature, se cambia solo la lista, no se agregan keys.
   - El call site es un `for (final f in features) ListTile(...)` que es
     trivial de testear.
   - Trade-off: no se puede traducir cada feature independientemente en
     runtime sin parsear (pero el ARB/list approach lo permite via
     indice).

2. **Price formato: estatico en l10n, NO `NumberFormat`**.
   `EsBO.paywallPrice = "$4.99"` (EnImpl) / `"$4,99"` (EsImpl). Razon:
   el precio del paywall **no se formatea con el locale del user** — la
   store cobra en USD fijo. Usar `NumberFormat` podria meter simbolos
   raros o separadores no-USD si el user tiene BOB configurado.
   Trade-off: si el precio cambia (de $4.99 a $6.99), hay que tocar
   ambos EsImpl y EnImpl. Aceptable porque el precio lo controla el
   Play Store y rara vez cambia.

3. **`paywallUnlockButton(price)` con placeholder**.
   `String paywallUnlockButton(String price)` → "Unlock for $price" /
   "Desbloquear por $price". El caller pasa el precio desde
   `EsBO.paywallPrice`. Asi un test puede verificar el label exacto
   sin hardcodear el precio en el test.

4. **`ref.listenManual` con `fireImmediately: true` en `initState`**.
   Spec pedia `ref.listen` para reaccionar a errores. La API de
   `flutter_riverpod` 2.6.1 no expone `fireImmediately` en `ref.listen`
   (solo en `listenManual`). Ademas, `ScaffoldMessenger.of(context)`
   no esta disponible en `initState` (InheritedWidgets se setean despues).
   Solucion: `listenManual` en `initState` + `addPostFrameCallback` en
   el callback para diferir la `showSnackBar` al proximo frame.
   - Tipo de `_errorSub` es `dynamic` porque `ProviderSubscription` no
     es parte de la API publica de `flutter_riverpod` (vive en
     `riverpod/src/framework/foundation.dart`).
   - Solo se usa `.close()` en `dispose`, asi que el cast dinamico
     no tiene costo runtime.

5. **Loading durante accion: NO usar `AsyncValue.loading()`**.
   El notifier (`EntitlementNotifier.purchase`) NO emite `AsyncValue.loading()`
   durante el await (devuelve el estado previo hasta que llega el resultado).
   Asi que la UI no muestra spinner al tap — uso un `_busy` local en
   `_FreeBody` para deshabilitar botones + mostrar spinner inline.
   Razon: si la red tarda 3-5s, no queremos reemplazar toda la UI con un
   spinner (perderiamos el precio + features). El spinner chico cerca
   del boton es menos disruptivo.

6. **Mock del notifier: notifier REAL + repos/payment fakes**.
   Los tests usan el `EntitlementNotifier` REAL con deps fakados
   (`_FakeRepo` + `_FakePaymentService`). Esto valida el wire entre
   widget y notifier, no solo UI aislada. Para los 2 tests de Loading
   y Error, subclassing `EntitlementNotifier` y override de
   `build()` para forzar el state deseado — patron estandar de
   Riverpod 2.x.

7. **AppBar con `leading: IconButton(close)` + sin title**.
   El spec asumia AppBar con titulo "3dCalc Pro", pero eso duplicaria
   el titulo del body (heading hero). Opte por AppBar minimalista con
   solo un icono X (close) para que el user pueda dismiss. El titulo
   del paywall vive solo en el body como hero. Esto es el patron
   estandar de paywalls en Material 3 (ver PaywallScreen de RevenueCat).
